# ADR-008: Server-Sent Events для real-time статуса платежа

## Status
Accepted

## Context

После создания платежа клиент перенаправляется на страницу оплаты провайдера. Когда пользователь возвращается обратно, фронтенд не знает актуальный статус — нужно либо:

1. **Polling**: фронтенд делает `GET /payments/{id}` каждые N секунд
2. **WebSocket**: двунаправленный канал, избыточен для одностороннего обновления
3. **SSE (Server-Sent Events)**: однонаправленный стрим сервер → клиент

Polling нагружает API лишними запросами и создаёт задержку до N секунд. WebSocket требует отдельного сервера или расширения (Soketi, Pusher, Reverb) — дополнительная инфраструктура.

## Decision

Используем **Server-Sent Events** через `GET /api/v1/payments/{id}/stream`.

Механизм:
```
Client                              Server
  |                                   |
  |-- GET /payments/{id}/stream ----> |
  |                                   |  (polling DB каждые 2с)
  |<-- event: status { ...payment } --|
  |<-- event: status { ...payment } --|  ← статус изменился
  |<-- event: close { status: "Succeeded" } --|
  |                                   |
  [EventSource.close()]               [соединение закрыто]
```

Правила:
- Стрим закрывается при терминальном статусе: `Succeeded`, `Cancelled`, `Refunded`
- Максимальное время жизни соединения — 5 минут (потом `event: timeout`, клиент переоткрывает)
- Заголовок `X-Accel-Buffering: no` отключает буферизацию Nginx
- Фронтенд показывает индикатор `Live` пока SSE подключён

## Consequences

**Плюсы:**
- Нативная поддержка в браузерах без библиотек (`EventSource` API)
- Автоматическое переподключение браузером при разрыве
- Один HTTP/1.1 keep-alive — меньше нагрузки чем N polling-запросов
- Не нужна дополнительная инфраструктура (нет Pusher/Reverb)

**Минусы:**
- PHP не нативно асинхронный — воркер FPM занят на всё время стрима (до 5 мин)
- При высокой нагрузке нужен пул FPM воркеров достаточного размера
- EventSource не поддерживает кастомные заголовки — X-Api-Key передаётся query-param
- HTTP/2 мультиплексирует SSE лучше, чем HTTP/1.1 (Nginx → рекомендуем HTTP/2 в prod)
