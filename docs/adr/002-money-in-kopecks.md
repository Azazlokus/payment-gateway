# ADR-002: Хранение денег в копейках (целые числа)

## Status
Accepted

## Context

Денежные суммы требуют точного представления. Альтернативы:
- `float` / `double` — стандартные типы PHP и большинства языков
- `string` с десятичной точкой — как возвращают провайдеры (`"500.00"`)
- `int` в минимальных единицах валюты (копейки для RUB)

Проблема float хорошо известна:
```php
echo 0.1 + 0.2; // 0.30000000000000004
echo 100.10 * 100; // 10009.999999999998
```

При накоплении ошибок округления в возвратах или разбивке чека по позициям — расхождения реальны.

## Decision

Все денежные суммы хранятся и передаются внутри системы как **`int` в копейках**.

Value Object `Money`:
```php
Money::ofRub(10000)  // 100.00 RUB
$money->amount()     // 10000 (int, копейки)
$money->formatted()  // "100.00"
```

Правила:
- Конвертация из строки провайдера: `(int) round((float)"500.00" * 100)`
- Конвертация в строку для провайдера: `number_format($kopecks / 100, 2, '.', '')`
- В БД: колонка `amount` типа `unsignedInteger` (копейки)
- В API-ответах: `amount` в копейках, `amount_formatted` в рублях для отображения
- Минимальная сумма: 100 копеек (1 рубль) — валидируется на входе

## Consequences

**Плюсы:**
- Целочисленная арифметика точна: `10000 + 5000 = 15000` без сюрпризов
- Простое хранение в БД без риска потери точности
- Легко сравнивать суммы: нет проблемы `0.1 + 0.2 != 0.3`

**Минусы:**
- Граница конвертации (строка провайдера ↔ int копейки) требует аккуратности
- `round()` при конвертации из float всё равно присутствует — но только на входе/выходе
- Разработчики должны помнить что `amount = 50000` — это 500 рублей
